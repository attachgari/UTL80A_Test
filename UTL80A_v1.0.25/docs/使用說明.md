# UTL80A v1.0.25 Fz 砝碼測試

## 使用方式

1. 解壓縮後在 Arduino IDE 開啟 [UTL80A_v1.0.25.ino](../arduino/UTL80A_v1.0.25/UTL80A_v1.0.25.ino)，選擇 Seeed XIAO nRF54L15 並上傳。
2. 執行 [Start-UTL80A.bat](../Start-UTL80A.bat)，在 Chrome 或 Edge 連接 USB 或藍牙。裝好治具，卸下砝碼並靜置，再按「手動歸零」。
3. 測垂直砝碼時，在「韌體換算」選「Fz 砝碼測試」，或在 Arduino 序列監控視窗送 `filter fz`。沿原有方向放砝碼，壓向讀值為負。選回「TCN」或送 `filter tcn` 可比較既有六軸輸出。
4. 開機預設為原六軸 TCN。砝碼測試只替換 Fz 的估算，其他五軸仍輸出原 TCN 讀值。網頁維持六軸、RAW 切換、2,000 筆歷史與 0 中心自動縮放。USB 和 BLE 的目標皆為 100 Hz。Arduino 序列監控視窗可送出 `rate` 查看實機的八路新資料與有效力量更新率。

## Fz 怎麼算

歸零後計算 `ΔRi = Ri − R0i`，以 `Fz = c1 × ΔR1 + … + c8 × ΔR8` 得到 N。八個係數全部由資料一起擬合，保留垂直施力在不同線圈上造成的響應。Fz 砝碼模式使用當筆八路，不需等待 TCN 歷史。

擬合以 0.5、1、1.5 kg 的 20 組垂直步進為主，每組各自扣除卸載段平均，取載入最後 1 秒的 RAW 平均。標記 Fz 的壓向載荷使用 `−m × 9.80665` N，這些案例只提供 Fz 標籤。既有校正資料作較弱約束，其中 Tz click 的名義 Fz 增量為零，權重再降低。用 `Fz_0` 的第 180–240 秒空載波動約束過大的噪聲增益，第 240–250 秒作驗證零點，第 250–300 秒驗證空載波動。0.0825、0.0951、0.4148 kg 的治具資料沒有當作這次的獨立砝碼步進或空載零點。

| 檢查 | Fz 砝碼模式 |
| --- | ---: |
| 留出同一輪重複編號的 RMSE | 1.90 N |
| 留出整批量測的 RMSE | 3.31 N |
| 留出整個重量級距的 RMSE | 3.32 N |
| 空載第 250–300 秒逐筆標準差 | 0.31 N |
| 正向 Tz click 峰值的 Fz 讀值 RMS | 17.00 N |

兩批標記 1 kg 的測試分開留出時，平均預測為 −8.61 N 與 −3.92 N，參考均為 −9.81 N。現有資料的批次差異是主要限制。Tz 測試的 Fz 讀值也會放大，所以本模式供垂直砝碼對照，混合六軸量測使用原 TCN。0.1 N 解析度及 ±1% FS 尚待整機以實際小步進與額定載荷驗證。完整數值見 [Fz 驗證結果](../reports/fz_validation_v1.0.25.json)。

## 下一批 ANSYS 資料怎麼接

每個案例可以同時有 Fx、Fy、Fz 和三軸力矩，也可以同時讓全部線圈的相對 X、Y、Z 位移或傾角改變。每一列保留同一載入案例的**六軸施加值與八顆線圈的預估 counts 變化**。若只有線圈的平移掃描，先用 X、Y、Z 局部斜率乘以 ANSYS 對應的相對位移並加總，留下傾斜響應這項未驗證的誤差。若日後有實測傾角響應，可將它加進各路預估 counts。模擬工況和基準的裝配、靶材、間隙及零點應相同。

CSV 欄名如下。力矩用 N·m，線圈用相對零點的 RAW counts。每列是完整的耦合案例。

```text
Fx_N,Fy_N,Fz_N,Tx_Nm,Ty_Nm,Tz_Nm,Delta_L1,Delta_L2,Delta_L3,Delta_L4,Delta_L5,Delta_L6,Delta_L7,Delta_L8
```

依 [README 的重建係數](../README.md#重建係數) 指令執行 `fit_fz.py`，加上 `--simulation` 和 CSV 路徑，重新產生 `fz_calibration.h` 後編譯上傳。程式只用這些案例的 Fz 參考值和八路輸入估計 Fz 列，六軸施加值用於保留工況來源。模擬案例合計權重是直接步進的 5%，實測留出評分只用實測資料。這次交付的係數使用現有量測，模擬案例數為 0。
